# הכנסות והוצאות

אפליקציית Android אישית, בעברית ומימין לשמאל, לניהול הכנסות והוצאות. מייבאים קבצי Excel/CSV מכרטיס Max ומחשבון הבנק (מזרחי-טפחות), והאפליקציה מסווגת, מחשבת כמה נשאר החודש, מציגה גרפים ומציעה איפה לחסוך.

**הכול נשמר בטלפון בלבד.** אין שרת, אין חשבון, אין אנליטיקס, ואפילו אין לאפליקציה הרשאת אינטרנט.

## מה יש בה

| מסך | תוכן |
|---|---|
| סקירה | כרטיס "כמה נשאר החודש", גרף מגמה חודשי, דונאט קטגוריות, בתי העסק הגדולים, תשלומים עתידיים |
| תנועות | חיפוש, סינון, תיקון סיווג (גם לכל בית העסק), מחיקה |
| חיסכון | פוטנציאל חיסכון חודשי ושנתי, כרטיסי הזדמנויות עם צעדים, השוואה לממוצע, מנויים וחיובים קבועים |
| עוד | ייבוא קבצים, **ייצוא וגיבוי JSON**, **שחזור מגיבוי**, הכנסה צפויה, מחיקת נתונים |

כללים שחשוב להכיר:

- **חיוב כרטיס אשראי בבנק לא נספר כהוצאה.** כדי שלא ייספר פעמיים, שורת "מקס איט / ישראכרט / כאל" בחשבון הבנק מסווגת כהעברה, וההוצאות נלקחות מפירוט הכרטיס עצמו. כך גם חיסכון והעברות פנימיות.
- **תשלומים:** תשלום בעסקת תשלומים משויך לחודש לפי תאריך החיוב, כי אז הכסף באמת יוצא. תשלומים שעוד לא נגבו מוצגים בכרטיס "תשלומים בדרך".
- **חודשים חלקיים:** חודש שהנתונים לא מכסים מסומן "חלקי". בחישובי ממוצע ובסיס חיסכון משתמשים בחודשים שלמים בלבד (ואם אין, בהערכה מנורמלת).
- **מניעת כפילויות:** אפשר לייבא קבצים חופפים או את אותו קובץ שוב; תנועה שכבר קיימת לא תוכפל. שתי קניות זהות באותו יום נשמרות כשתיים.

## התקנה בטלפון (APK), צעד אחר צעד

האפליקציה נבנית בענן של Expo (שירות EAS), ולכן לא צריך Android Studio ולא צריך שהמחשב יישאר מחובר אחרי ההתקנה.

### 1. התקנת Node.js (פעם אחת)
הורד והתקן את גרסת LTS מ-<https://nodejs.org>. בדוק בטרמינל:
```
node -v
```

### 2. יצירת חשבון Expo חינמי (פעם אחת)
היכנס ל-<https://expo.dev/signup>, צור חשבון ואמת את המייל. זה בחינם.

### 3. התקנת eas-cli (פעם אחת)
```
npm install -g eas-cli
```

### 4. התחברות
```
eas login
```
הזן את שם המשתמש והסיסמה של חשבון Expo.

### 5. הכנת הפרויקט
```
cd expenses-app
npm install
eas init
```
`eas init` יצור את הפרויקט בחשבון שלך וישמור את המזהה שלו ב-`app.json`. אשר כשהוא שואל.

### 6. בניית ה-APK
```
eas build -p android --profile preview
```
- אם נשאלת "Generate a new Android Keystore?" ענה **Yes**. המפתח נשמר בחשבון Expo שלך, והוא מה שמאפשר לעדכן את האפליקציה בעתיד על גבי הקיימת.
- הבנייה רצה בענן ולוקחת בדרך כלל 10 עד 30 דקות (בחשבון חינמי יש תור). אפשר לסגור את הטרמינל ולעקוב בכתובת <https://expo.dev> ← Builds.
- בסוף תקבל קישור ו-QR להורדת קובץ ה-APK.

### 7. הורדה והתקנה בטלפון
1. פתח את הקישור (או סרוק את ה-QR) **בטלפון** והורד את קובץ ה-APK.
2. פתח את הקובץ שהורד. אם Android חוסם, יופיע חלון "מטעמי אבטחה הטלפון שלך לא מורשה להתקין אפליקציות ממקור זה". לחץ **הגדרות** ואפשר **"התקנה ממקורות לא ידועים" / "Install unknown apps"** לדפדפן (או לאפליקציית הקבצים) שממנה הורדת.
3. חזור ולחץ **התקן**. אם Play Protect מזהיר, בחר **"התקן בכל זאת"** (זו אפליקציה שבנית בעצמך).
4. פתח את "הכנסות והוצאות", לחץ על "ייבוא קבצים" ובחר את הקבצים.

## גיבוי ושחזור

- **עוד ← ייצוא גיבוי** יוצר קובץ JSON עם כל התנועות וההגדרות ופותח את תפריט השיתוף של Android (שמור ב-Drive, במייל, בקבצים).
- **עוד ← שחזור מגיבוי** טוען קובץ כזה. אפשר לבחור **מיזוג** (מוסיף רק מה שחסר) או **החלפה** (מוחק את הקיים ומחליף בגיבוי).
- מומלץ לייצא גיבוי לפני כל עדכון ולפני החלפת טלפון. התקנת גרסה חדשה **על גבי** הקיימת שומרת את הנתונים, אבל **הסרת האפליקציה מוחקת אותם**.
- האפליקציה מוגדרת בלי גיבוי אוטומטי של Google (`allowBackup: false`) כדי שהנתונים לא יצאו מהמכשיר. לכן הגיבוי הידני הוא הדרך היחידה להעביר נתונים לטלפון חדש.

## עדכון גרסה בעתיד

1. פתח את `app.json` והעלה שני ערכים:
   - `"version"`: מספר שמוצג למשתמש, למשל `"1.0.1"`.
   - `"android"` ← `"versionCode"`: מספר שלם שחייב לעלות בכל בנייה (1 ← 2 ← 3 ...). בלי זה Android לא יתקין את הגרסה החדשה על הישנה.
2. הרץ שוב `eas build -p android --profile preview`.
3. הורד את ה-APK החדש והתקן אותו **על גבי** הקיים. הנתונים נשארים.

## פרטיות ואבטחה

- הנתונים נשמרים ב-AsyncStorage בתוך האחסון הפרטי של האפליקציה.
- ב-`app.json` הרשאת `INTERNET` חסומה, כלומר האפליקציה טכנית לא יכולה לשלוח מידע החוצה.
- אין אנליטיקס, אין שירותים חיצוניים, והפונטים והאייקונים מצורפים לאפליקציה.
- כדי לפתח עם Expo Go או עם שרת פיתוח צריך להסיר זמנית את `blockedPermissions` מ-`app.json`.
- קבצי בנק ואשראי אסור להעלות לגיט: `samples/`, `*.xlsx`, `*.csv` וקבצי גיבוי כבר מוחרגים ב-`.gitignore`.

## תאימות לבנייה עצמאית

כל הספריות שבשימוש הן מודולי Expo/React Native שנכללים בבנייה עצמאית, ואין שימוש ב-API שקיים רק ב-Expo Go:

| צורך | ספרייה |
|---|---|
| בחירת קבצים | `expo-file-system` (`File.pickFileAsync`) |
| שמירת נתונים | `@react-native-async-storage/async-storage` |
| גרפים | `react-native-svg` |
| שיתוף הגיבוי | `expo-sharing` |
| פענוח Excel/CSV | `xlsx` (JavaScript טהור) |
| פונט Heebo ואייקונים | `@expo-google-fonts/heebo`, `@expo/vector-icons` (מצורפים לאפליקציה) |

בדיקה שנעשתה בסביבת הפיתוח: `npx expo export --platform android` מקמפל בהצלחה את כל האפליקציה לחבילת Hermes. לא הורצה בנייה מלאה על מכשיר אמיתי, ולכן ההתקנה הראשונה בטלפון היא גם הבדיקה האמיתית הראשונה.

## פיתוח

```
npm install
npm run typecheck      # tsc --noEmit
npm run lint           # expo lint
npm run check-files    # בדיקות פירוק, סיווג, כפילויות, חודשים חלקיים, תשלומים, חיסכון וגיבוי
npm run check-files -- path/to/max.xlsx path/to/bank.xlsx   # פירוק קבצים אמיתיים והדפסת סיכום
npm start              # שרת פיתוח (Expo Go)
```

אם קיימת תיקיית `samples/` בשורש הפרויקט, `npm run check-files` יפרק גם את כל הקבצים שבה.

### מבנה הקוד

```
src/app/            מסכים (Expo Router): (tabs)/index, transactions, savings, more, import
src/ui/             theme, רכיבים, גרפים (SVG), סרגל לשוניות
src/parsers/        קריאת Excel/CSV, זיהוי כותרות, פירוק כרטיס אשראי ובנק
src/categorize.ts   סיווג לפי כללי משתמש, בנק, בתי עסק מוכרים וקטגוריית הקובץ
src/importer.ts     מזהים יציבים ומניעת כפילויות
src/insights.ts     סיכומים חודשיים, חודשים חלקיים, "כמה נשאר", תשלומים עתידיים
src/advice.ts       פוטנציאל חיסכון, הזדמנויות, השוואה לממוצע, מנויים
src/backup.ts       יצירה ובדיקה של קובץ גיבוי
src/store.tsx       מצב האפליקציה ושמירה מקומית
scripts/            check-files.ts, make-demo-data.ts, make-icons.py
```

### הערה על פורמט הקבצים

הפירוק מזהה את שורת הכותרות לפי שמות העמודות (למשל "תאריך עסקה", "שם בית העסק", "סכום חיוב", "חובה", "זכות") ולא לפי מיקום, ולכן הוא סובל שורות כותרת לפני הטבלה, כמה גיליונות וקידוד עברית ישן ב-CSV. הוא נכתב ונבדק על קבצים שנוצרו לפי המבנה הידוע של Max ובנק מזרחי. אם קובץ אמיתי לא מזוהה, הרץ `npm run check-files -- הקובץ.xlsx` ותראה מה נקרא, ושלח את שורת הכותרות כדי שאוסיף את השמות החסרים ל-`SYNONYMS` ב-`src/parsers/table.ts`.
